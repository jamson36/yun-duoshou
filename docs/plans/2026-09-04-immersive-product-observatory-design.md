# “欲望观察舱”3D 交互设计

> 状态：M6“科技橱窗街”已完成本地实现与浏览器验证，等待用户体验验收
> 模式：交互机制借鉴（interaction adaptation）
> 更新：2026-09-04

## 0. 决策摘要

- **一句话体验**：从房间书桌掌机进入一条夜间科技橱窗街，镜头沿轨道巡游始终正对用户的商品广告屏；用户亲手关闭三座环绕展位的 3D 催促信号塔，点亮 24 小时冷静通道，再决定是否把商品放进冷静单。
- **场景等级**：Three.js 固定镜头 3D 展陈 + 语义化 DOM 商品层的混合场景。
- **标志性交互**：商品实拍图被诚实地呈现为橱窗广告屏，不再绕轴旋转；短拖动只改变镜头视差，横向滑动沿轨道切换展位。三座带本地短标签的 3D 信号塔可直接点击熄灭，灯光、雾和冷静门随之改变。
- **第一条纵向切片**：掌机入口 → 镜头进入科技橱窗街 → 横向巡游真实商品广告屏 → 直接关闭两个 3D 信号塔 → 冷静门由琥珀转为青色 → 打开既有预填冷静单 → 保存订单 → 返回房间看到既有订单角标更新。
- **P0 边界**：不自由行走、不做人物、碰撞、多人、音频、在线模型、外部 3D 模型或重型多 Pass 后处理；不改变订单、目标、评分和 AI 的事实来源。
- **兼容决定**：公开深链继续使用 `#room?activity=peel`，避免破坏旧链接；`peel` 仅保留为内部兼容标识，用户可见名称统一改为“欲望观察舱”。

## 2. 目标、非目标与成功标准

### 目标

1. 解决原玩法中文字来不及阅读、节奏过快、目标逻辑不直观的问题。
2. 让“商品本身”和“催促购买的信号”在空间上明确分层：商品可看，信号可关，商品不会被切碎。
3. 保留项目底层含义：活动帮助用户争取决定时间，不替用户判断商品好坏，也不把克制包装成道德优越。
4. 与既有商城和订单复用同一份事实；活动只选择和解释，不直接写订单。
5. 让鼠标、触摸、键盘、可选手势和减少动态模式都能完成同一条路径。

### 非目标

- 不建设可漫游商城、开放世界、角色控制、物理碰撞或任务系统。
- 不导入 GLB/VRM、参考站模型、外部 CDN、远程字体或音频。
- 不保存“关闭了哪些信号”、场景角度、游玩次数、分数或排行榜。
- 不通过 AI 生成商品、价格、话术结论或消费建议。
- 不以 Canvas 承载商品详情、表单和关键操作。

### 可量化成功标准

- 进入后首个可用操作不依赖 3D 加载，500ms 内可见语义商品信息和控制按钮。
- 用户可以不限时停留，商品名称与价格始终静止可读。
- 桌面 1440×1000、平板 768×900、手机 390×844 和 375×812 无页面级横向溢出。
- 键盘可完成商品切换、镜头观察、关闭信号、进入冷静单和退出。
- WebGL 创建或着色失败时显示完整 DOM 商品替代，不白屏、不阻断订单预填。
- 活动隐藏、标签页隐藏或面板切换时停止动画帧；DPR 上限 1.6，常态只保留当前和相邻两席高分辨率展品。
- 活动内不出现超过两行的即时反馈；解释性长文只存在于不移动的详情区域。

## 3. 三种实现方案

| 方案 | 产品价值 | 成本与风险 | 决定 |
| --- | --- | --- | --- |
| DOM/SVG 2.5D | 最轻、可访问性最好、开发快 | 商品旋转和空间光感不足，无法形成用户期待的独立 3D 空间 | 拒绝作为主方案，仅作为 WebGL 失败回退 |
| 混合 WebGL + DOM | 有真实深度、直接操控和氛围变化，表单与文字仍稳定可读 | 需要维护场景与 DOM 的单向同步 | **采用** |
| 完整 Three/WebGPU 自由漫游 | 表现力最强，可接复杂模型和后处理 | 引入构建链、重依赖、模型资产、控制教学与移动端成本；空间移动并非消费缓冲的核心动作 | P0 拒绝 |

## 4. 场景与对象地图

| 对象或区域 | 含义 | 路由或动作 | 数据驱动变化 | 非空间替代 |
| --- | --- | --- | --- | --- |
| 中央广告屏 | 当前正在观察的商品实拍图 | 始终正对用户，不接受商品自身旋转 | 最近一笔个人冷静单可成为优先商品 | 商品标题、类别、金额和静态商品图 |
| 左右雾中展位 | 上一个 / 下一个本地商品 | 横向滑动、按钮或方向键驱动镜头轨道切换 | 使用版本化本地商品池，顺序确定性 | “上一个”“下一个”按钮和商品标签 |
| 三座 3D 信号塔 | 限时、从众、凑单等外部推动力 | Canvas 射线点击熄灭；DOM 按钮用 Enter 或 Space 等价操作 | 最近订单的结构化触发优先，否则按商品 ID 确定性选择 | 带按下状态的语义按钮组 |
| 环境噪声层 | 推动力强弱的视觉投影 | 随关闭信号减少抖动、扫描与高频色彩 | 只来自当前瞬态信号状态 | 文本状态“还有 N 个催促信号” |
| 24 小时冷静门 | 从即时决定转向缓冲流程 | 两座信号塔熄灭后由琥珀转青并显现通道状态 | 不保存游戏进度，只投影当前瞬态状态 | 稳定问题与“进入冷静通道”按钮 |
| 冷静单接口 | 把商品交给既有业务流程 | 打开既有订单或预填表单 | 复用商城映射；活动本身不创建订单 | “放进冷静单”按钮 |
| 返回门 | 退出观察舱 | 关闭、Esc、浏览器后退 | 无业务写入 | “回到房间”按钮 |

## 5. 状态与导航模型

### 路由状态

```text
#room                         房间
#room?activity=peel           欲望观察舱（兼容旧深链）
#new?view=home&type=<type>    由观察舱交接到现有模拟手机
#orders                       当前商品已经是冷静单时的交接目标
```

活动选择、镜头偏移、已关闭信号不写入 URL；刷新活动深链时重新进入一个确定性的初始商品状态。

### 场景状态

```text
CLOSED → ENTERING → INSPECTING ↔ SWITCHING
                       ↕
                    SUSPENDED
任意可见状态 → FALLBACK（WebGL 失败，DOM 继续）
任意状态 → LEAVING → CLOSED
```

- `ENTERING` 只负责 360–460ms 的掌机原点显影，不阻断 DOM 控件。
- `INSPECTING` 接受镜头拖动、横向滑动、键盘、3D 信号塔 / 语义按钮和手势视差。
- `SWITCHING` 采用 320ms 内的相机/商品交接；重复输入合并到最后一次选择。
- `SUSPENDED` 停止 RAF，不释放可复用几何；恢复后重置帧时间，避免跳帧。
- `FALLBACK` 隐藏 Canvas，显示稳定的商品实拍图和全部语义控件。

### 数据状态

活动只持有可丢弃状态：

```text
selectedProductId
cameraOffsetX / cameraOffsetY
dismissedSignalIds: Set
hoveredSignalId
inputMode: pointer | keyboard | gesture
renderMode: webgl | fallback
```

订单仍由 `app.js` 现有状态与保存流程负责。活动通过 `onIntent({type:'cool', focusItem})` 交接，不写 LocalStorage。

### AI 状态

本功能不发起 AI 请求，不新增同意或请求状态。商品事实和反思提示均为版本化本地内容。

### 返回、刷新、深链与 Esc

- 从掌机进入时记录真实热点按钮；退出后镜头归位并把焦点还给它。
- 直接加载活动深链时，退出聚焦房间画布。
- 浏览器后退与 Esc 均退出活动；活动中的 DOM 焦点循环不进入背景。
- 从活动交接到预填表单后，返回遵循既有“商品表单 → 模拟手机 → 房间”层级。

## 6. 交互规格

1. 点击真实掌机后，房间镜头聚焦掌机；橱窗从该物件屏幕位置显影，随后一次性完成约 500ms 的镜头推入，标题和退出按钮从第一帧即可操作。
2. 中央商品实拍图明确安装在橱窗广告屏内，始终正对用户且不绕轴旋转；左右两席在雾中建立连续街区。短拖动、触摸拖动或手势移动镜头视差，超过阈值的横向滑动切换展位；页面本身不移动，滚轮不被劫持。
3. 左右箭头或 `ArrowLeft/ArrowRight` 同样切换商品；相机沿轨道平移，旧橱窗退入雾中，新橱窗与信息同步进入，不等待动画结束才开放操作。
4. 三座 3D 信号塔布置在商品屏前后不同深度，显示“今晚恢复”“都在抢”“一步到位”等本地短标签。指针或触摸可直接命中，DOM 按钮保持完全等价；关闭时塔体断电收束、连线熄灭、噪声减少并播报剩余数量。
5. 关闭两个信号后，背景冷静门从琥珀警告态切换为青色开放态，并出现稳定问题：“24 小时后，你还会主动想起它吗？”不自动消失、不要求回答。
6. “放进冷静单”复用既有订单：已有个人冷静单则进入该订单；本地商品则打开预填表单；用户仍需明确保存才产生记录。
7. “先离开”不保存活动状态，直接返回房间。全过程不计时、不扣分、不制造胜负。

## 7. 系统架构

```text
Hash 路由（app.js）
   ├─ 房间/活动互斥与焦点返回
   ├─ 订单与商城事实
   └─ intent adapter
          │
          ▼
desire-observatory.js
   ├─ 瞬态观察状态
   ├─ 产品与信号确定性选择
   ├─ 输入归一化（pointer/keyboard/gesture）
   ├─ 点击与滑动判定（signal pick / camera rail）
   └─ scene adapter（无业务写入）
          │
          ├─ desire-observatory-scene.js：Three 街区、镜头轨道、广告屏、信号塔射线拾取、冷静门、光雾与资源释放
          └─ DOM：标题、金额、按钮、状态、fallback
```

计划文件职责：

- `desire-observatory.js`：产品定义、信号选择、瞬态状态、输入和业务 intent 控制器。
- `desire-observatory-scene.js`：独立 Three 场景适配器，只接收可丢弃的视觉快照。
- `desire-observatory.css`：独立视觉层、响应式、减少动态和 WebGL fallback。
- `index.html`：稳定的语义 DOM 结构，不把文字画进 Canvas。
- `app.js`：继续持有路由、房间互斥、手势权限和订单交接。
- `scene-config.js`：保留真实掌机坐标，只更新用户可见名称和说明。
- `server.mjs` / `Dockerfile`：显式公开和打包新增根级模块。

控制器继续兼容当前协调器所需的方法：`open`、`close`、`destroy`、`applySegment`、`pause`、`resume`。这样活动重构不会扩散到订单与全景引擎。

## 8. 本地数据与导出

- 不新增 LocalStorage schema，不保存观察舱状态。
- 读取订单时只接收调用方提供的快照；优先展示最近一笔非演示“冷静中”记录。
- 当前订单商品不一定有专属图片：无法精确映射时按已有本地品类选择可复现的替代图，并明确保留用户输入的真实名称与金额；不生成假商品图。
- “放进冷静单”只发出 intent；真实保存、迁移、导出、重置继续走现有实现。
- 活动状态不进入 JSON/CSV 导出，避免把一次视觉练习伪装成消费事实。

## 9. AI 合同与安全

本功能无 AI 调用、无新增 API、无新增网络权限。它不会计算人格、金额、消费结论，不修改诊断状态，也不会把商品名称、订单或手势数据发送到服务端。

## 10. 响应式、无障碍与减少动态

- **1440 桌面**：Canvas 全幅成为科技街区，顶部只保留标题与退出；商品档案、信号和操作压缩为下方悬浮信息带，三座信号塔在画面内保持可点但不遮挡商品。
- **768 平板**：固定纵深场景，信息带分成商品信息、信号、动作三段；切换按钮位于画面两侧，滑动阈值不与页面滚动冲突。
- **390/375 手机**：固定较近机位，商品屏与信号塔占据上方主体，底部信息带收敛为紧凑网格；允许横向滑动切换但不产生页面级滚动。
- Canvas `aria-hidden="true"`；外层使用可聚焦区域并提供操作说明。商品切换与信号关闭均有真实按钮。
- `ArrowLeft/ArrowRight` 切商品，`ArrowUp/ArrowDown` 轻移镜头高度，`Enter/Space` 操作当前聚焦信号按钮，`Esc` 返回。
- 所有目标至少 44×44px，焦点清晰；状态通过 `aria-live="polite"` 播报，不靠颜色表达。
- 减少动态时取消漂浮、扫描线移动、镜头插值和信号塔位移；商品选择用淡入，直接拖动仍可用。

## 12. 性能预算

- 首个 DOM 操作：活动打开后 500ms 内可用，不等待 WebGL。
- JS：本地 vendor Three 构建约 700KB（含 core）；业务与场景源码合计目标小于 110KB，不引入构建链或运行时 CDN。
- 图形：不加载 GLB/视频；最多三张商品纹理同时保持高关注度，远景使用同一轻量几何；常态绘制调用目标小于 70。
- DPR：上限 1.6；连续慢帧时降为 1.2，并关闭远景粒子、次要光带与阴影。
- 帧率：桌面目标 55–60fps；中端移动目标 30fps；连续 20 帧超过 28ms 进入降级。
- 暂停：`document.hidden`、活动关闭、业务面板打开时停止 RAF；恢复时不累计离屏时间。
- 最大可选增强：未来仅在有原创、可授权模型和真实设备预算后替换单个程序化商品，不整体升级为自由漫游。

## 14. 有意偏差与待决策

| 项目 | 参考行为 | 本项目行为 | 原因 | 重新考虑条件 |
| --- | --- | --- | --- | --- |
| D1 场景规模 | 自由行走城市 | 固定观察舱与直接操控商品 | 空间移动不是消费缓冲目标 | 用户测试证明探索本身能提升完成率 |
| D2 渲染栈 | Three WebGPU + TSL + 多层后处理 | MIT Three.js WebGLRenderer + 原创单场景材质、雾、发光 Sprite 与 CSS 纹理层 | 原生低模已被实际验收证明达不到识别度；仍不引入参考引擎或重型后处理 | 中端手机无法维持 30fps |
| D3 内容节奏 | 连续动态场景与任务 | 无计时、用户主动推进 | 文字必须看得清，决定不能被活动催促 | 无 |
| D4 交互浮标 | 3D 射线图集 | 3D 信号塔提供射线命中，底部 DOM 按钮提供键盘 / 读屏等价操作；商品屏保持固定正面 | 兼顾空间直操、稳定阅读和可访问性 | 无 |
| D5 资产 | 大体量模型、贴图、音视频 | 项目既有商品图作为纹理，空间结构程序化生成 | 商品识别度高、权利边界清晰、加载可控 | 获得独立原创 3D 商品模型 |
| D6 声音 | 环境音乐与反馈音 | P0 静音 | 不抢占注意力、不增加权限和素材成本 | 用户明确要求且有原创音频 |

## 15. 里程碑

1. **M0 设计与边界**：完成本设计、机制登记和实施账本。
2. **M1 初版纵向切片（已由 M5 / M6 替代）**：一个程序化商品、旋转、三个信号、订单预填、返回与 WebGL fallback。
3. **M2 初版商品扩展与手势（已由 M6 替代）**：六类程序化商品、确定性切换、最近冷静单、平滑手势旋转。
4. **M3 响应式与韧性**：375/390/768/1440、键盘、减少动态、暂停和慢帧降级。
5. **M4 初版视觉（未通过）**：程序化低模与左右控制台完成自动化，但用户验收判定缺少真实商品、空间叙事和精致度；保留提交作为回退，不继续换皮。
6. **M5 空间重构与证据（本地完成）**：Three 固定镜头橱窗、真实商品展牌、光雾与镜面层次、极简 HUD、完整浏览器矩阵均已完成；当前停在用户本地视觉验收门。
7. **M6 科技橱窗街（本地完成）**：取消单面商品图旋转，把拖动改为镜头视差与横向巡游；新增可射线命中的 3D 信号塔和状态驱动的 24 小时冷静门；桌面、平板、手机与减少动态验证已完成，等待用户本地体验验收。
