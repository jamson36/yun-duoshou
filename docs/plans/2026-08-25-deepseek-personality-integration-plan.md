# 消费人格与 DeepSeek 接入实施计划

> 日期：2026-08-25
> 部署目标：阿里云 Linux 服务器
> 运行形态：单体同源 Node 服务，无数据库

## 已确认方案

- 左侧健身区“消费测试”热点继续作为入口，内容在现有诊疗终端面板中展开。
- 五维分数、动机占比、行为结果和主/副人格由浏览器内确定性规则计算。
- DeepSeek 读取去标识化汇总，负责模式解读、一步建议和目标关联，不能修改本地分数。
- Node 服务同时托管静态页面和 `/api/ai/diagnosis`，避免跨域。
- `DEEPSEEK_API_KEY` 只存在于阿里云服务器环境变量。
- 默认模型使用当前 DeepSeek 官方推荐的 `deepseek-v4-flash`，关闭思考模式以控制延迟。

## Step 1：本地评分引擎

- 输出：`personality-scoring.js`，提供 7/30 天统计、五维评分、四类动机、结果指标、人格匹配、置信度和 AI 汇总。
- 兼容：旧订单字段缺失时安全降级；新增 `decisionSignals`、`decidedAt`、`statusHistory`。
- 测试：不足 3 条不出人格、缺失维度不伪装 50 分、时间窗口生效、请求不含商品名与备注。

## Step 2：消费测试屏与联动

- 输出：周期切换、评分刻度、主/副人格、动机、行为结果、证据说明、发送摘要确认、DeepSeek 状态和降级提示。
- 订单联动：下单时最多选择两个决策动作；状态变化记录决定时间与历史；任何数据变化使旧 AI 结果过期。
- 测试：3 笔门槛、同意前无网络请求、拒绝后本地评分可用、旧诊断过期、海报可使用本地人格。

## Step 3：阿里云后端

- 输出：`server.mjs`、DeepSeek 适配器、环境变量示例、Docker Compose 与 Caddy 配置。
- 安全：请求尺寸限制、内存限流、12 秒内超时、JSON 输出、服务端与前端双重字段校验、安全响应头、不记录完整输入输出。
- 测试：健康检查、静态资源、缺少密钥、无效输入、上游错误和合法结构。

## Step 4：文档与完整验证

- 输出：更新 PRD、DESIGN 和 README，固定 DeepSeek 技术选择与新评分规则。
- 自动化：`npm test`、语法检查、API 假上游集成测试。
- 浏览器：桌面与移动端分别验证空数据、演示数据、本地结果、AI 同意、成功、失败降级和减少动态。
