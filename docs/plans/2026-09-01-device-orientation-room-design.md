# 手机体感环视设计

## 目标

在支持设备方向传感器的触屏手机上，把全景房间的辅助控制从摄像头手势切换为“体感环视”。用户主动开启后，左右转动手机用于环视，轻微上下倾斜用于调整视角；双指缩放、触摸拖拽、顶部三个语义入口和键盘控制全部保留。桌面端继续提供现有摄像头手势，不把两类权限混在同一个入口里。

## 交互与边界

- 手机端进入房间后显示“体感”按钮；点击先查看用途说明，再由“开启体感环视”触发系统权限请求。
- 当前设备姿态作为零点。首个稳定方向数据完成校准，之后使用低通平滑、微小死区和单帧速度上限驱动全景。
- 水平环视允许连续转动；上下视角仍服从全景相机现有边界。屏幕横竖方向改变时自动以新姿态重新校准，避免突然跳转。
- 开启后可以随时“重新校准”或“关闭体感”。触摸拖拽始终可用，不支持、拒绝权限或没有传感器数据时只显示降级提示。
- 体感不使用摄像头，不保存方向数据，不调用本站接口，也不触碰订单、目标、评分、诊断或其他业务事实。
- 进入功能面板、页面隐藏、启用减少动态效果或页面销毁时立即移除传感器监听；返回房间后不自动重启。

## 实现结构

- `orientation-controls.js`：纯函数完成角度归一、屏幕方向修正、跨 360° 解包、平滑、死区和速度限制。
- `orientation-ui.js`：管理设备能力判断、权限、校准、状态文案和监听生命周期，只把角度增量交给全景。
- `panorama.js`：新增受现有交互锁和动态偏好约束的角度增量入口。
- `index.html` / `styles.css`：增加手机体感说明与控制面板；支持体感的触屏设备隐藏摄像头手势入口，桌面布局不变。
- `server.mjs`：同源公开新增模块，并显式允许当前源使用加速度计与陀螺仪；麦克风、定位、磁力计和支付继续禁用。

## 验收

自动化覆盖角度跨界、横竖屏修正、死区、速度上限、重新校准、权限拒绝、减少动态和面板生命周期。浏览器覆盖 390×844、768px 与 1440×1000 的入口切换、弹层、触摸兜底和无横向溢出。桌面浏览器的合成方向事件只证明页面链路；最终手机手感需由真实设备确认。
