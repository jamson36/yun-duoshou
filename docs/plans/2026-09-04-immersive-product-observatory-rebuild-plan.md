# “欲望观察舱”交互重建实施账本

> 模式：交互机制借鉴
> 产品决策源：`docs/plans/2026-09-04-immersive-product-observatory-design.md`

## 0. 工作规则

1. 只借鉴通用机制，不复制未授权的表达、源码或资产。
2. 参考事实、产品决定、实现状态和浏览器证据分别记录。
3. 先完成单条纵向切片，再扩商品、手势与装饰效果。
4. Canvas 只负责空间视觉，DOM 负责所有关键文字和业务操作。
5. 活动只发出 intent，订单、目标、评分和 AI 事实仍由现有模块维护。
6. 每个里程碑按功能独立提交；未通过本地验证不进入下一批。

## 1. 机制清单

| 表面 | 触发 | 状态变化 | 反馈 | 采用决定 | 溯源 |
| --- | --- | --- | --- | --- | --- |
| 场景与路由同步 | 进入/后退/深链 | room ↔ activity | 镜头聚焦、活动显隐、焦点恢复 | 采用现有 Hash 路由，场景只投影 | 当前项目 `app.js` / `route-sync.js` |
| 固定镜头聚焦 | 选择区域或作品 | idle → focused | 位置与 FOV 缓动 | 转译为 360–460ms 掌机到观察舱、320ms 商品切换 | 参考仓库 camera/state 机制；原创实现 |
| 可检查对象 | 指针/键盘 | inspect → rotate/select | 直接旋转、轮廓发光 | 采用商品拖动与基础拾取 | 参考仓库 raycast 原则；原创实现 |
| 发光、雾与故障噪声 | 状态变化 | noisy → calm | emissive 减弱、雾色变暖、扫描降频 | 克制采用；减少动态和慢帧可关闭 | 参考仓库 post/fog 分层原则；原创着色 |
| 当前项 + 相邻预览 | 左右切换 | selected index 改变 | 中央清晰、两侧弱化 | 采用最多 3 个高细节实体，不加载视频 | 参考仓库 active 2 + lookahead 1 预算原则 |
| 信号浮标 | 点击/Enter/Space | active → dismissed | 浮标收束、环境降噪、状态播报 | 使用 DOM 按钮，不把文字画进 3D | 本项目原创产品语义 |
| 手势连续控制 | 指向移动 | pointer segment → rotation | 平滑跟手、丢手暂停 | 复用现有本地手势权限和 mapper | 当前项目 `peel-gesture-controls.js` |
| 业务交接 | “放进冷静单” | activity → existing flow | 打开订单或预填表单 | 复用 `onIntent`，活动不写数据 | 当前项目 `handlePeelGameIntent` |

## 2. 待验证架构假设

| 假设 | 重要性 | 验证动作 | 结果 |
| --- | --- | --- | --- |
| 无依赖原生 WebGL 足以呈现精致的商品观察感 | 决定是否需要 Three.js/构建链 | M1 用程序化模型做 1440/390 同屏检查，再由用户验收 | **不成立**：用户确认低模像调试器，商品不可读、没有完整空间叙事；M5 改用本地 Three.js + 既有商品实拍图 |
| 无计时的“旋转 + 关信号”比抛接玩法更易理解 | 决定是否替换旧交互 | 本地演示后请用户直接判断玩法含义和精致度 | 操作、信息层级和无计时路径已通过浏览器验证；产品感受仍待用户验收 |
| DOM 浮标不会削弱 3D 沉浸 | 决定可访问与表现的平衡 | 桌面、手机截图与键盘完整流程 | **部分不成立**：右侧大档案把体验变成控制台；M5 仅保留底部轻量信息带与固定短信号 |
| 现有 `onIntent` 足以完成业务纵切 | 防止活动另造订单事实 | 从商品进入预填、保存、回房间检查角标 | 预填与零写入通过；保存继续沿用既有回归 |
| 程序化几何在移动端预算内 | 决定模型策略 | 慢帧诊断、DPR 降级、390px 浏览器验证 | 性能成立但商品识别与审美失败；改为最多三席的压缩本地商品纹理，仍需真实手机 GPU 验收 |

## 4. 有意偏差

| ID | 参考行为 | 产品行为 | 原因 | 重新考虑条件 |
| --- | --- | --- | --- | --- |
| O1 | 自由漫游、碰撞与教学任务 | 固定观察台 | 最短路径直达消费缓冲动作 | 真实测试证明漫游有业务价值 |
| O2 | WebGPU/TSL/Three 与多 Pass | MIT Three.js WebGLRenderer + 原创单场景光雾，不复制参考引擎或后处理 | 实际验收证明原生低模表现失败；保留 WebGL2 覆盖和移动预算 | 中端手机无法维持 30fps |
| O3 | 大量模型与媒体 | 既有商城商品图作为三席展牌纹理，空间几何程序化生成 | 商品识别度、许可和加载预算兼顾 | 获得原创商品 GLB 与明确预算 |
| O4 | 3D 内文字图集 | 语义 DOM 浮标 | 键盘、读屏和稳定阅读 | 无障碍等价能力成熟 |
| O5 | 持续动态与游戏目标 | 无计时、无得分、主动推进 | 产品不能用新的紧迫感对抗消费紧迫感 | 无 |

## 6. 风险

| 风险 | 可能性 | 影响 | 缓解 | 状态 |
| --- | --- | --- | --- | --- |
| 3D 变成纯装饰，逻辑仍不清楚 | 中 | 高 | 交互只保留“看商品—关信号—再决定”，无计时与长漂浮文案 | 浏览器路径通过，待用户体验验收 |
| 程序化模型显得廉价 | 已发生 | 高 | 停止在旧版换皮；真实商品图成为视觉主体，3D 只负责展牌厚度、空间、镜头与光雾 | M5 本地修复完成，待用户验收 |
| 手机 GPU 慢或 WebGL 不可用 | 中 | 高 | DPR/实体/效果硬上限、慢帧降级、DOM fallback | 浏览器降级通过，真实设备待验收 |
| 活动误写订单或重复创建 | 低 | 高 | 只发 intent，复用既有订单映射与保存流程 | 自动化与浏览器预填零写入通过 |
| 手势旋转再次出现卡顿 | 中 | 中 | 沿用时间常数平滑，手势只控制单一旋转自由度，丢手重置时间基准 | 自动化通过，真实摄像头待验收 |
| 新根级模块未进入白名单或镜像 | 中 | 高 | 同步 `PUBLIC_ROOT_FILES`、Dockerfile 和服务器测试 | 白名单、镜像清单与服务测试通过 |

## 7. 里程碑日志

### M0 — 设计与隔离（2026-09-04）

- **产出**：建立独立分支 `feat/immersive-product-gallery` 和项目内忽略的工作树；完成体验、架构、性能、无障碍、来源和验证决定。
- **参考证据**：本地只读研究 `samsyninja-rebuild` SHA `2716e96` 的路由/状态、相机、交互、作品切换与后处理分层；没有复制源码或资产。
- **发现**：最有价值的是状态分离、固定镜头、直接拾取、发光/雾随状态变化和小型活跃资源池；自由行走、VAT、多人和大型媒体均不服务本项目核心行为。
- **下一入口**：新增 `desire-observatory.js` 与语义 DOM，先完成一个商品、三个信号、WebGL fallback 和订单预填纵切。

### M1–M2 — 场景纵切与六类商品（2026-09-04）

- **产出**：新增 `desire-observatory.js` / `.css`，以原创单 Pass WebGL 和程序化几何实现耳机、奶茶、键盘、跑鞋、相机、盲盒六类商品；`app.js` 只通过 intent 连接既有订单或预填表单。
- **交互证据**：指针拖动可改变观察角度，聚焦舞台后左右方向键切换商品、上下方向键与 `A / D` 调整角度；切换后当前商品信号重新生成。
- **业务证据**：点击“放进冷静单”进入 `#new?view=home` 并预填商品名、金额、分类和原因，房间摘要仍为 0；未确认保存前不产生订单。
- **工程证据**：根级静态白名单与 Dockerfile 已包含新 JS / CSS；兼容旧 `activity=peel` 深链，旧运行模块不再由入口加载。

### M3–M4 — 降级、视觉与完整回归（2026-09-04）

- **桌面浏览器**：1440×1000 下真实 WebGL、拖动、键盘切换、关掉两条信号后展示稳定问题、预填交接均通过；从真实掌机打开后按 `Esc` 回到 `#room`，焦点恢复到 `desire-peel`。
- **响应式**：375×812、390×844、768×900、1440×1000 的 `body` 与活动弹层宽度均不超过视口，移动端使用单列内部滚动，桌面端保持舞台 / 档案双栏。
- **降级**：减少动态时质量为 `essential`；通过 `WEBGL_lose_context` 强制上下文丢失后切为静态商品视图，Canvas 隐藏、fallback 显示，10 个可见按钮仍可操作。
- **质量门**：完整 `npm test` 为 `394/394`；必需 JavaScript 语法检查、`git diff --check` 与 Compose 配置检查通过；本轮 Playwright 控制台 0 错误、0 警告。
- **边界**：上述均为本地浏览器证据；真实手机 GPU、真实触控、真实摄像头手势、生产部署和真实用户审美判断尚未完成。

### M4 用户验收失败与 M5 重构入口（2026-09-04）

- **验收结论**：初版自动化、路由和降级正确，但视觉不合格；程序化跑鞋不可识别，大块左右控制台压缩了空间，材质、雾、反射和镜头缺少共同叙事。
- **参考实机证据**：已恢复参考仓库 107 个资产（206.2MB）并真实启动 SHA `2716e96`，检查 Explore / Works / About。确认其完成度来自完整环境、前后景尺度、发光信息面、黑色距离雾、地面反射、持续相机状态和克制 HUD 的组合，而非黑底荧光配色本身。
- **重构决定**：保留当前提交作为可回退点；M5 用 MIT Three.js 建一个原创固定镜头夜间橱窗，以项目既有商品图作有厚度展牌，只保留稳定底部信息带。继续复用现有路由、信号状态、订单 intent、手势和无障碍控制。
- **下一入口**：先完成一件跑鞋与左右相邻展位的空间纵切，再接六件商品、信号降噪、移动与 fallback。

### M5 — 夜间商品展陈重构（2026-09-04）

- **产出**：彻底移除上一版原生 WebGL 低模渲染器，新增独立 `desire-observatory-scene.js`；用本地 Three.js、项目既有六类商品实拍图、厚度展牌、雾中相邻展位、橙青光轨、反射与粒子组成原创固定镜头夜间展陈。
- **界面**：大块左右控制台改为稀疏顶部标题和底部玻璃信息带；商品名、价格、切换、催促信号与业务动作全部保持稳定 DOM。两次降噪后才显示静态问题“24 小时后，你还会主动想起它吗？”。
- **交互修复**：舞台拖动会跳过按钮、链接与表单控件，修复“下一件”点击被指针拖动吞掉的问题；按钮与 `ArrowRight` 均已真实切换商品，信号状态在切换后重置。
- **响应式证据**：1440×1000、768×900、390×844 与 375×667 均完成本地浏览器检查；390×844 与 375×667 的 `body` 宽高均等于视口，关键内容单屏可见、无页面级滚动或横向溢出。
- **质量门**：完整 `npm test` 为 `395/395`；相关 JavaScript 语法检查、`git diff --check` 通过；最终浏览器控制台 0 错误、0 警告。
- **证据文件**：`output/playwright/night-window-1440-v5.png`、`output/playwright/night-window-768-v5.png`、`output/playwright/night-window-390-v5.png`；这些是本地浏览器证据，不代表真实手机 GPU、摄像头手势或生产环境验收。
- **当前门禁**：本地服务保留在 `127.0.0.1:8787` 供用户验收；未获得本轮确认前不上传、不部署。
